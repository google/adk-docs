# M91 human-in-the-loop for ADK

<div class="language-support-tag">
  <span class="lst-supported">Supported in ADK</span><span class="lst-typescript">TypeScript</span>
</div>

[M91](https://m91.msg91.com/) by MSG91 is an alerting service that rings a
person's phone at full volume, through silent mode and Do Not Disturb, and
escalates to a voice call until somebody answers. The
[`@msg91comm/m91`](https://www.npmjs.com/package/@msg91comm/m91) SDK uses it to
put a human in the loop of an ADK agent: before a tool you name runs, a phone
rings with Approve and Reject buttons, and the tool runs only if a person
approves.

## Use cases

- **Approval before irreversible actions**: Gate refunds, payouts, deletions
  and production deploys behind a person's explicit approval, using an
  `LlmAgent`'s `beforeToolCallback`. The model cannot skip the check.

- **Fail-closed by default**: A rejection, no answer within the timeout, or an
  M91 error all mean the tool does not run. The agent receives the reason as
  the tool's result and can explain it to the user.

- **Agent-initiated questions**: Give the agent an `m91_request_approval` tool
  so it can decide to ask a person when it is unsure, and an `m91_send_alert`
  tool to wake somebody about something that happened without waiting.

## Prerequisites

- Install the [M91 app](https://play.google.com/store/apps/details?id=com.msg91.m91)
  and create a channel with at least one member
- Copy the channel's send link (the paper-plane icon on the channel). It is a
  credential: keep it in an environment variable, never in source control

## Installation

```bash
npm install @google/adk @msg91comm/m91 zod
```

## Use with agent

```typescript
import { FunctionTool, LlmAgent } from "@google/adk";
import { M91Client } from "@msg91comm/m91";
import {
  createM91BeforeToolCallback,
  createM91Tools,
} from "@msg91comm/m91/integrations/google-adk";
import { z } from "zod";

const client = new M91Client(process.env.M91_SEND_LINK!);

const issueRefund = new FunctionTool({
  name: "issue_refund",
  description: "Refund an order to the original payment method.",
  parameters: z.object({ orderId: z.string(), amountInr: z.number() }),
  execute: async ({ orderId, amountInr }) => ({
    status: "refunded",
    orderId,
    amountInr,
  }),
});

export const rootAgent = new LlmAgent({
  name: "support_agent",
  model: "gemini-flash-latest",
  instruction:
    "Resolve refund requests. If a refund is rejected, tell the customer why.",
  tools: [issueRefund, ...(await createM91Tools(client))],
  // issue_refund rings a phone first and runs only if a person approves.
  beforeToolCallback: createM91BeforeToolCallback(client, {
    tools: ["issue_refund"],
    timeoutSeconds: 600,
  }),
});
```

## Available tools

Tool | Description
---- | -----------
`m91_request_approval` | Ask a person for permission and wait for the answer. Returns `approved`, `rejected`, or an error that must be treated as a no
`m91_send_alert` | Wake somebody about something that happened, without waiting for an answer

## Configuration

`createM91BeforeToolCallback(client, options)` accepts:

Option | Description
------ | -----------
`tools` | The tool names that need a person's approval, or a function `(name, args) => boolean`. Other tools run without a phone call
`timeoutSeconds` | How long to wait for an answer before treating it as a rejection. Default `300`
`severity` | `LOW`, `MEDIUM`, `HIGH` (default) or `CRITICAL`. Only `CRITICAL` always escalates to a voice call
`approveLabel`, `rejectLabel` | The button labels on the phone. Default `Approve` and `Reject`
`describe` | A function `(call) => ({ title, description })` to write the lock-screen text yourself

The callback waits for the answer in-process, so the agent run stays open
while the phone rings.
