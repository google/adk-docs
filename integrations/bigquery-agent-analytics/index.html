BigQuery Agent Analytics plugin for ADK¶

Supported in ADKPython v1.21.0Go v0.1.0Java v1.5.0Kotlin v0.8.0

The BigQuery Agent Analytics Plugin significantly enhances Agent Development Kit (ADK) by providing a robust solution for in-depth agent behavior analysis. Using the ADK Plugin architecture and the BigQuery Storage Write API, it captures and logs critical operational events directly into a Google BigQuery table, empowering you with advanced capabilities for debugging, real-time monitoring, and comprehensive offline performance evaluation.

The plugin also provides Auto Schema Upgrade (safely add new columns to existing tables), Tool Provenance tracking (LOCAL, MCP, SUB_AGENT, A2A, TRANSFER_AGENT, TRANSFER_A2A, TOOLBOX, SKILL), HITL Event Tracing for human-in-the-loop interactions, and Automatic View Creation (generate flat, query-friendly event views).

Support for ADK 2.0 multi-agent workflows extends tracing to agent transfers, state checkpoints, event compaction, and long-running tools in Python and Go. It adds four workflow event types: AGENT_TRANSFER, AGENT_STATE_CHECKPOINT (in Go, emitted when checkpoint keys are enabled in CustomMetadataAllowlist), EVENT_COMPACTION, and TOOL_PAUSED. It also stamps an attributes.adk envelope on every row so you can reconstruct the agent execution graph and join a paused tool to the row that resumes it. In Java, this support currently covers the TOOL_PAUSED event and its pause/resume pairing keys only (without the attributes.adk envelope). See Agent workflow and pause/resume events (ADK 2.0) for details.

The plugin includes three reliability and observability capabilities (Java: v1.7.0 or later; Go):

  • Cross-region Storage Write API routing. Writes to BigQuery datasets outside the US multi-region (for example EU or northamerica-northeast1) now route to the region that owns the write stream. Previously they could fail with a "session not found" / stream-not-found error and silently drop every row.
  • Delivery and content-incident observability. Delivery losses are tracked per reason. Python and Go also count formatter failures (and Python counts parser failures) where a sentinel row is written. The counters are exposed through BigQueryAgentAnalyticsPlugin.get_drop_stats() (Python), DropStats() (Go, via agentanalytics.AsBigQueryAgentAnalyticsPlugin), or getDropStats() (Java), so a host can poll and export them to its own monitoring. The reason keys and semantics differ per language; see Dropped-event observability.
  • No duplicate spans in Cloud Trace. When Agent Engine telemetry (GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true) or any other Cloud Trace exporter is wired to the global tracer provider, the plugin no longer produces a duplicate span next to each framework span. The plugin still inherits trace_id from the ambient OTel span, so BigQuery rows continue to join cleanly to Cloud Trace traces.

In Python (v2.7.0 and later) and Go, every row also receives a stable 32-character hexadecimal event_id before it enters the write queue. The ID is preserved across Storage Write API retries, so consumers can identify retry duplicates. An opt-in exactly_once_delivery (ExactlyOnceDelivery in Go) mode uses committed streams and explicit offsets to prevent duplicates from ambiguous retries within a live processor. This mode does not guarantee lossless delivery, and stream-rotation / ResourceExhausted retry handling differs between Python and Go; see Delivery and deduplication.

Python (v2.7.0 and later) and Go also capture model and workflow termination details. Final LLM_RESPONSE rows include finish_reason and, when supplied by the model, a sanitized error_message. Workflow nodes can emit NODE_OUTPUT and NODE_ERROR, and agent or run failures emit AGENT_ERROR and INVOCATION_ERROR (in Go, AGENT_ERROR also covers failed activations that ADK handles without an AfterAgent callback).

In ADK Python v2.13.0 and later, the plugin adds:

  • Tool result error classification (tool_result_classifier and ToolResultClassification), alongside built-in detection of MCP tool results with isError=True / is_error=True and ReflectAndRetryToolPlugin error answers, so tools that report failures in their return value instead of raising an exception are recorded as TOOL_ERROR rows.
  • Agent evaluation views (create_eval_views=True, or on-demand await plugin.create_eval_views()), which create v_eval_session and v_eval_turn views that reconstruct AgentData evaluation traces directly in BigQuery.

BigQuery Storage Write API

This feature uses BigQuery Storage Write API, which is a paid service. For information on costs, see the BigQuery documentation.

Kotlin support

The Kotlin plugin logs invocation lifecycle events. It writes an INVOCATION_STARTING row when an invocation begins and an INVOCATION_COMPLETED row when it ends, and creates the partitioned, clustered events table on first use if it does not already exist.

Rows are inserted one at a time through tabledata.insertAll, synchronously on the invocation path, rather than through the Storage Write API used by Python, Go, and Java.

The following are not implemented in Kotlin: LLM, tool, agent, state, HITL and A2A events; the ADK 2.0 workflow events; automatic view creation; Auto Schema Upgrade; tool provenance; GCS offloading; and drop statistics.

Use cases¶

  • Agent workflow debugging and analysis: Capture a wide range of plugin lifecycle events (LLM calls, tool usage) and agent-yielded events (user input, model responses), into a well-defined schema.
  • High-volume analysis and debugging: Logging operations are performed asynchronously using the Storage Write API to allow high throughput and low latency.
  • Multimodal Analysis: Log and analyze text, images, and other modalities. Large files are offloaded to GCS, making them accessible to BigQuery ML via Object Tables.
  • Distributed Tracing: Built-in support for OpenTelemetry-style tracing (trace_id, span_id) to visualize agent execution flows.
  • Tool Provenance: Track the origin of each tool call (local function, MCP server, sub-agent, A2A remote agent, transfer agent, Toolbox tool, or Skill toolset).
  • Human-in-the-Loop (HITL) Tracing: Dedicated event types for credential requests, confirmation prompts, and user input requests.
  • Agent Workflow Tracing (ADK 2.0): Capture agent transfers, state checkpoints, event compaction, and long-running tool pause/resume, with an attributes.adk envelope for reconstructing the execution graph.
  • Queryable Event Views: Automatically create flat, per-event-type BigQuery views (e.g., v_llm_request, v_tool_completed) to simplify downstream analytics by unnesting JSON payload data.

Installation¶

Install ADK with the dedicated BigQuery Agent Analytics extra. The extra includes the BigQuery clients, Cloud Storage client, and pyarrow required by the plugin:

pip install "google-adk[bigquery-analytics]>=2.7.0"

The pyarrow dependency is no longer included in the general gcp extra. If pyarrow is missing, the plugin's import error identifies the bigquery-analytics extra to install.

The Go plugin is published as an independent Go submodule (plugin/agentanalytics/go.mod) in the adk-go repository so that core ADK applications do not pull in the BigQuery and Cloud Storage client dependencies unless needed. The Go plugin is versioned separately from core google.golang.org/adk/v2 (module google.golang.org/adk/plugin/agentanalytics, without a /v2 major-version suffix; tagged as plugin/agentanalytics/v0.1.0 starting in plugin release v0.1.0, which is what Go v0.1.0 in the support badges denotes). Install core ADK Go (v2.0.0+) and the plugin module with go get (@latest resolves to the latest tagged release, or pin an explicit plugin release such as google.golang.org/adk/plugin/agentanalytics@v0.1.0):

go get google.golang.org/adk/v2@latest
go get google.golang.org/adk/plugin/agentanalytics@latest

Quickstart¶

Add the plugin to your agent's App object. For prerequisites, see Prerequisites.

agent.py
import os
from google.adk.agents import Agent
from google.adk.apps import App
from google.adk.models.google_llm import Gemini
from google.adk.plugins.bigquery_agent_analytics_plugin import BigQueryAgentAnalyticsPlugin

os.environ['GOOGLE_CLOUD_PROJECT'] = 'your-gcp-project-id'
os.environ['GOOGLE_CLOUD_LOCATION'] = 'us-central1'
os.environ['GOOGLE_GENAI_USE_ENTERPRISE'] = 'True'

plugin = BigQueryAgentAnalyticsPlugin(
    project_id="your-gcp-project-id",
    dataset_id="your-big-query-dataset-id",
)

root_agent = Agent(
    model=Gemini(model="gemini-flash-latest"),
    name='my_agent',
    instruction="You are a helpful assistant.",
)

app = App(
    name="my_agent",
    root_agent=root_agent,
    plugins=[plugin],
)

Create the plugin with agentanalytics.NewBigQueryAgentAnalyticsPlugin and pass it to runner.New via PluginConfig. Because ADK Go's runner does not close plugins automatically, call defer bqPlugin.Close() inside your run function to flush buffered events and release BigQuery clients before exiting. For prerequisites, see Prerequisites.

main.go
package main

import (
    "context"
    "fmt"
    "log"

    "google.golang.org/adk/plugin/agentanalytics"
    "google.golang.org/adk/v2/agent"
    "google.golang.org/adk/v2/agent/llmagent"
    "google.golang.org/adk/v2/model/gemini"
    "google.golang.org/adk/v2/plugin"
    "google.golang.org/adk/v2/runner"
    "google.golang.org/adk/v2/session"
    "google.golang.org/genai"
)

func run(ctx context.Context) error {
    bqPlugin, err := agentanalytics.NewBigQueryAgentAnalyticsPlugin(
        ctx,
        "your-gcp-project-id",
        "your-big-query-dataset-id",
        "agent_events",
    )
    if err != nil {
        return fmt.Errorf("create BigQuery plugin: %w", err)
    }
    defer bqPlugin.Close()

    model, err := gemini.NewModel(ctx, "gemini-flash-latest", &genai.ClientConfig{
        Project:  "your-gcp-project-id",
        Location: "us-central1",
        Backend:  genai.BackendVertexAI,
    })
    if err != nil {
        return fmt.Errorf("create model: %w", err)
    }

    myAgent, err := llmagent.New(llmagent.Config{
        Name:        "my_agent",
        Model:       model,
        Instruction: "You are a helpful assistant.",
    })
    if err != nil {
        return fmt.Errorf("create agent: %w", err)
    }

    sessionService := session.InMemoryService()
    r, err := runner.New(runner.Config{
        AppName:        "my_agent",
        Agent:          myAgent,
        SessionService: sessionService,
        PluginConfig: runner.PluginConfig{
            Plugins: []*plugin.Plugin{bqPlugin},
        },
    })
    if err != nil {
        return fmt.Errorf("create runner: %w", err)
    }

    sessResp, err := sessionService.Create(ctx, &session.CreateRequest{
        AppName: "my_agent",
        UserID:  "demo_user",
    })
    if err != nil {
        return fmt.Errorf("create session: %w", err)
    }

    userMsg := genai.NewContentFromText("Hello!", genai.RoleUser)
    for _, err := range r.Run(ctx, "demo_user", sessResp.Session.ID(), userMsg, agent.RunConfig{}) {
        if err != nil {
            return fmt.Errorf("run error: %w", err)
        }
    }
    return nil
}

func main() {
    if err := run(context.Background()); err != nil {
        log.Fatal(err)
    }
}

BigQueryAnalyticsExample.kt
import com.google.adk.kt.agents.Instruction
import com.google.adk.kt.agents.LlmAgent
import com.google.adk.kt.apps.App
import com.google.adk.kt.models.Gemini
import com.google.adk.kt.plugins.agentanalytics.BigQueryAgentAnalyticsPlugin
import com.google.adk.kt.plugins.agentanalytics.BigQueryLoggerConfig

val analyticsAgent =
    LlmAgent(
        name = "my_agent",
        model = Gemini(name = "gemini-flash-latest"),
        instruction = Instruction("You are a helpful assistant."),
    )

/**
 * Wraps [analyticsAgent] in an [App] whose invocations are logged to BigQuery.
 *
 * The plugin creates the day-partitioned table on first use, so the credentials
 * in scope need permission to create a table in the dataset, not only to insert
 * rows. Without explicit `credentials`, application default credentials are used.
 *
 * Logging failures never fail the turn: a table that cannot be created, or a row
 * that cannot be inserted, is logged and the invocation carries on.
 */
fun analyticsApp(
    projectId: String,
    datasetId: String,
    datasetLocation: String,
): App {
    val plugin =
        BigQueryAgentAnalyticsPlugin(
            config =
                BigQueryLoggerConfig(
                    projectId = projectId,
                    datasetId = datasetId,
                    // Defaults to "US"; pass your dataset's location instead.
                    location = datasetLocation,
                ),
        )

    return App(
        appName = "my_agent",
        rootAgent = analyticsAgent,
        plugins = listOf(plugin),
    )
}

The plugin creates the events table on first use, so the credentials in scope need permission to create a table in the dataset, not only to insert rows. Set location to your dataset's location; it defaults to "US". For the full set of options, see Configuration options.

Logging never fails the turn: if the table cannot be created or a row cannot be inserted, the plugin logs the error and the invocation continues. When rows are missing, enable logging for com.google.adk.kt.plugins.agentanalytics.BigQueryAgentAnalyticsPlugin — logs are emitted under that class name, not under the plugin's ADK name (bigquery_agent_analytics).

Run and test agent¶

Test the plugin by running the agent and making a few requests through the chat interface, such as "tell me what you can do" or "List datasets in my cloud project ". These actions create events which are recorded in your Google Cloud project BigQuery instance. Once these events have been processed, you can view the data for them in the BigQuery Console, using this query:

SELECT timestamp, event_type, content
FROM `your-gcp-project-id.your-big-query-dataset-id.agent_events`
ORDER BY timestamp DESC
LIMIT 20;

import os
import google.auth
from google.adk.apps import App
from google.adk.plugins.bigquery_agent_analytics_plugin import BigQueryAgentAnalyticsPlugin, BigQueryLoggerConfig
from google.adk.agents import Agent

# --- OpenTelemetry note (no setup required for BQAA) ---
# The BQAA plugin does NOT export OTel spans of its own. It tracks the
# parent-child hierarchy on an internal stack: the root invocation span
# reuses the ambient OTel span's id (as a 16-hex string) when one is
# active, and child BQAA spans are generated internally as 16-hex
# strings. The plugin's `trace_id`
# column inherits from whichever OpenTelemetry span is active in the
# surrounding runtime when the agent runs:
#   * Agent Engine wires its invocation span automatically, so
#     `trace_id` in BigQuery joins to Cloud Trace out of the box.
#   * Locally, framework-instrumented runners open an invocation span
#     for you.
#   * If neither is available, the plugin falls back to a per-invocation
#     trace_id and the parent-child hierarchy is still preserved in
#     BigQuery; no OTel setup needed.
# Setting a bare `TracerProvider` with no ambient span will NOT cause
# `trace_id` to be populated with a "real" OTel id; only an *active*
# span does. See the "Tracing and observability" section for details.

# --- Configuration ---
PROJECT_ID = os.environ.get("GOOGLE_CLOUD_PROJECT", "your-gcp-project-id")
DATASET_ID = os.environ.get("BIG_QUERY_DATASET_ID", "your-big-query-dataset-id")
# GOOGLE_CLOUD_LOCATION must be a valid Agent Platform region (e.g., "us-central1").
# BQ_LOCATION is the BigQuery dataset location, which can be a multi-region
# like "US" or "EU", or a single region like "us-central1".

type ReverseArgs struct {
    Input string `json:"input" jsonschema:"Text to reverse."`
}

func reverseString(_ agent.Context, args ReverseArgs) (map[string]any, error) {
    runes := []rune(args.Input)
    for i, j := 0, len(runes)-1; i < j; i, j = i+1, j-1 {
        runes[i], runes[j] = runes[j], runes[i]
    }
    return map[string]any{"reversed": string(runes)}, nil
}

        Project:  projectID,

    }

        Name:        "bq_demo_agent",

Prerequisites¶

  • Google Cloud Project with the BigQuery API enabled.
  • BigQuery Dataset: Create a dataset to store logging tables before using the plugin. The plugin automatically creates the necessary events table within the dataset if the table does not exist.
  • Google Cloud Storage Bucket (Optional): If you plan to log multimodal content (images, audio, etc.), creating a GCS bucket is recommended for offloading large files.
  • Authentication:
    • Local: Run gcloud auth application-default login.
    • Cloud: Ensure your service account has the required permissions.
Note: Gemini model selector gemini-flash-latest

Most code examples in ADK documentation use gemini-flash-latest to select the latest available Gemini Flash version. However, if you access Gemini from a regional endpoint, such as us-central1, this selection string may not work. In that case, use a specific model version string from the Gemini models page or Google Cloud Gemini models list.

IAM permissions¶

For the agent to work properly, the principal (e.g., service account, user account) under which the agent is running needs these Google Cloud roles:

  • roles/bigquery.jobUser at Project Level to run BigQuery queries.
  • roles/bigquery.dataEditor at Dataset Level (or Table Level if the events table already exists and automatic view creation is disabled) to create or upgrade the events table, create the per-event-type views (Python and Go create views by default), and write log/event data.
  • If using GCS offloading: roles/storage.objectCreator and roles/storage.objectViewer on the target bucket.

If your principal has roles/bigquery.dataEditor only on the target table, table creation and automatic view creation (create_views=True in Python, DisableCreateViews: false in Go) will fail. Either grant roles/bigquery.dataEditor on the dataset, or pre-create the table and views from a deployment step (create_views=False in Python; DisableCreateViews: true in Go plus bqPlugin.SyncViews(ctx) or cfg.ViewDefinitions()). In Go, background view-creation failures are logged only when a non-default Logger is configured on agentanalytics.Config, so setting Logger is recommended.

Trace correlation, metadata capture, and column projection¶

Supported in ADKPython v2.4.0

Three options control what extra context lands in attributes and whether payload columns are written at all. Each is listed in the BigQueryLoggerConfig options table above; the notes below add the cross-option rules the flat table can't express:

  • enable_otel_correlation: The captured span context is a best-effort Cloud Trace correlation key, not a foreign key; when disabled (the default) no attributes.otel is written.
  • custom_metadata_allowlist: Leaving it unset preserves the previous behavior, where only the built-in a2a:* capture runs. Keys are read from event.custom_metadata. In ADK Python v2.12.0 and later, final (non-partial) LLM_RESPONSE rows read them from llm_response.custom_metadata. Captured values pass the same safety pipeline as all other logged content (truncation, sensitive-key redaction, circular-reference handling).
  • payload_column_denylist: Only content, content_parts, attributes, and latency_ms may be listed; identity and correlation columns are protected and raise ValueError. The projection is applied schema-first, so the table schema, the written rows, and the auto-created views stay consistent (views drop derived columns that depend on a denied column). Denying attributes also disables attributes.otel and attributes.custom_metadata, and combining it with a non-empty custom_metadata_allowlist is rejected at construction.
config = BigQueryLoggerConfig(

    custom_metadata_allowlist=["ticket_id", "exp:*"],  # capture selected custom_metadata keys

Final-answer capture and end-of-run flushing¶

Use final_response_tool_names when an agent delivers its final answer by calling a dedicated tool instead of yielding a plain-text final event. On a successful matching tool call, the plugin writes the tool's call arguments as an AGENT_RESPONSE row and adds source_tool to attributes.

The flush_on_run_end option defaults to True, which makes after_run_callback wait for the current event loop's write queue. Set it to False to remove that flush from the response path; the background writer will continue draining the queue, so rows may appear in BigQuery shortly after the run returns. In Python v2.10.0 and later, this setting also moves the writer to the shared background writer.

config = BigQueryLoggerConfig(
    final_response_tool_names=frozenset({"submit_final_response"}),
    flush_on_run_end=False,
)

Shared background writer¶

Supported in ADKPython v2.10.0

When flush_on_run_end=False, the plugin runs its batch writer on a dedicated, process-lifetime background event loop thread instead of the caller's event loop. Set use_dedicated_background_loop=True to use that thread even when flush_on_run_end=True, or False to keep the writer on the caller's event loop.

Plugin instances in the same process that target the same table with equivalent credentials share one background writer and BigQuery write client, so short-lived plugin instances, such as one per request, don't each open a new writer. Equivalence is derived from the credential identity (for example, the service account email, scopes, and project). Set credentials_identifier to choose explicitly which plugin instances share a writer. Use the same identifier only for instances with equivalent credentials and writer settings: the shared writer uses the credentials and writer settings, such as batch_size and retry_config, of the instance that creates it.

Calling shutdown() or close() with default arguments detaches the plugin instance from the shared writer but leaves the writer running, so queued rows continue to be written. At interpreter exit, the plugin makes a best-effort attempt to drain active writers. To drain and stop the shared writer explicitly, for example at the end of a standalone script or a test, pass close_background_transport=True or call close_shared_background_transports():

# Drain and stop the shared writer for this plugin's table and credentials.
await plugin.close(close_background_transport=True)

# Or drain and stop every shared background writer in the process.
await BigQueryAgentAnalyticsPlugin.close_shared_background_transports(timeout=10.0)

Delivery and deduplication¶

Supported in ADKPython v2.7.0Go v0.1.0

Every row receives a 32-character hexadecimal event_id before enqueue. The same ID is reused when the Storage Write API retries that row, making it the deduplication key in the default delivery mode:

SELECT *
FROM `your-gcp-project-id.adk_agent_logs.agent_events`
QUALIFY
  event_id IS NULL
  OR ROW_NUMBER() OVER (PARTITION BY event_id ORDER BY timestamp) = 1;

The event_id IS NULL condition retains rows written before the column was introduced.

Set exactly_once_delivery=True (ExactlyOnceDelivery: true in Go) to use a committed stream and explicit offsets. This prevents a retry whose first result was ambiguous from creating a duplicate within the lifetime of that processor. It can consume additional BigQuery CreateWriteStream quota when a stream must be rotated.

config = BigQueryLoggerConfig(exactly_once_delivery=True)

Despite its name, this option is not a lossless-delivery guarantee. Batches can still be dropped after retry exhaustion, an offset conflict, or a replacement-stream failure. After a failed stream rotation, events arriving during the 30-second rotation backoff are also dropped. Monitor the offset_conflict (AppendFailureDrops in Go) and other drop reasons, and retain event_id as a consumer deduplication key.

In Go (cfg.ExactlyOnceDelivery = true), stream rotation and retry classification differ slightly from Python:

  • After OutOfRange, NotFound, or an unexpected AlreadyExists, Go replaces the committed stream (at most once per batch) and resends the batch within the same append, unless the stream was rotated by an earlier batch and has not committed yet (in which case Go drops the batch and pauses rotation) or an earlier attempt of the batch had an unknown outcome (in which case OutOfRange or NotFound drops the batch to prevent duplicates and replaces the stream before the next batch). Python drops the batch after any of the three and replaces the stream before the next batch.
  • On an RPC-level receive error after a successful Send, Go treats Unavailable, DeadlineExceeded, Canceled, Aborted, Internal, and Unknown as unknown outcomes, whereas Python also treats ResourceExhausted (TooManyRequests) as an unknown outcome.

Table readiness callbacks¶

Supported in ADKPython v2.12.0

Use on_schema_error and on_schema_ready to observe the table readiness check that the plugin runs during setup. The check reads, creates, or upgrades the BigQuery table and creates any requested views.

  • on_schema_error is called with the exception each time the check fails to read, create, or upgrade the table. It fires at most once per check, so it can be called repeatedly while setup retries. It isn't called when a view can't be created or a label-only table refresh fails; the plugin logs those failures and continues.
  • on_schema_ready is called with no arguments each time the check succeeds, which means that the table exists or was created or upgraded and every requested view was created.

Both callbacks run on a worker thread, not the event loop, so keep them fast and non-blocking. Exceptions that a callback raises are logged and suppressed. Values that aren't synchronous callables raise ValueError when the plugin is constructed.

After a successful check, later setups of the same plugin skip it, including after close(), after a fork, and in copies pickled afterwards. Neither callback fires again, and later table outages appear only as dropped rows when rows are written. Later setups run the check again only if the setup that was waiting for it was cancelled, or after a create_analytics_views() call fails to create a view. A create_analytics_views() call that creates every view makes later setups skip the check, and its own view creation never invokes either callback.

If you serialize the plugin with the standard pickle module, the callbacks must be picklable, for example module-level functions. Lambdas and closures can't be pickled with pickle, and bound methods pickle their instance.

Tool result error classification¶

Supported in ADKPython v2.13.0

Many tools return structured error payloads instead of raising an exception. In ADK Python v2.13.0 and later, after_tool_callback evaluates every tool result in three steps:

  1. ReflectAndRetryToolPlugin error answers (identified by response_type) are always recorded as TOOL_ERROR using error_details or error_type. Moreover, when a tool raises an exception that on_tool_error_callback has already recorded, a later plugin's fallback answer is skipped in after_tool_callback so the same failure is never logged twice. Register BigQueryAgentAnalyticsPlugin before retry plugins such as ReflectAndRetryToolPlugin so it observes every raised error directly.
  2. Custom tool_result_classifier: When configured on BigQueryLoggerConfig, the plugin calls tool_result_classifier(tool=..., tool_args=..., tool_context=..., result=...). The classifier must be synchronous and return a ToolResultClassification(status="ERROR" | "OK", error_message=...) or None:
  3. status="ERROR" logs the call as TOOL_ERROR with status="ERROR" and the supplied error_message (or a fixed default message when omitted). The tool result itself is omitted from TOOL_ERROR content so unformatted error payloads are not written into content. Note that content_formatter and payload_column_denylist do not apply to error_message, so copy tool output into error_message only when storing that text is acceptable.
  4. status="OK" logs the call as TOOL_COMPLETED, even if the built-in MCP rule below would have flagged it.
  5. None leaves the decision to the built-in rule.
  6. Built-in MCP isError / is_error rule: Any dict result or MCP CallToolResult model whose top-level isError or is_error is True is recorded as TOOL_ERROR with the fixed message "Tool returned an MCP result with isError=true.".
from google.adk.plugins.bigquery_agent_analytics_plugin import (
    BigQueryLoggerConfig,
    ToolResultClassification,
)

def classify_tool_result(*, tool, tool_args, tool_context, result):
    if isinstance(result, dict) and result.get("status") == "ERROR":
        return ToolResultClassification(
            status="ERROR",
            error_message=result.get("error_code", "tool returned status=ERROR"),
        )
    return None  # Fall back to the built-in MCP isError / is_error check

config = BigQueryLoggerConfig(
    tool_result_classifier=classify_tool_result,
)

Agent evaluation views¶

Supported in ADKPython v2.13.0

Set create_eval_views=True on BigQueryLoggerConfig (or call await plugin.create_eval_views() on demand) to create two views that reconstruct google.cloud.aiplatform.v1beta1.AgentData evaluation traces in a trace (JSON) column alongside per-session and per-turn rollup metrics:

  • {view_prefix}_eval_session (default v_eval_session): One row per session_id with session-level metrics (turn_count, tool_call_count, tool_error_count, llm_error_count, agent_error_count, has_error, has_truncated_content, has_tool_loop, max_consecutive_identical_tool_calls, distinct_tools_used, total_prompt_tokens, total_completion_tokens, total_tokens, total_latency_ms, eval_ready) and the multi-turn trace.
  • {view_prefix}_eval_turn (default v_eval_turn): One row per (session_id, invocation_id) turn with turn_index, turn-level metrics (turn_latency_ms, token and error counts, eval_ready), and a single-turn trace whose inner turn_index is 0.

In ADK Python v2.13.0, evaluation views require content (putting "content" in payload_column_denylist raises ValueError) and all 15 events listed below. Filtering out a required event in event_allowlist / event_denylist is rejected; this release has no conversation-only evaluation mode:

  • USER_MESSAGE_RECEIVED, AGENT_STARTING, LLM_REQUEST, TOOL_STARTING, TOOL_COMPLETED, TOOL_PAUSED, AGENT_TRANSFER, HITL_CREDENTIAL_REQUEST, HITL_CONFIRMATION_REQUEST, HITL_INPUT_REQUEST, HITL_CREDENTIAL_REQUEST_COMPLETED, HITL_CONFIRMATION_REQUEST_COMPLETED, HITL_INPUT_REQUEST_COMPLETED, AGENT_RESPONSE, and INVOCATION_COMPLETED.

Because the views aggregate across the table by session_id / invocation_id, filtering on session_start_timestamp or turn_start_timestamp does not prune the base table's timestamp partitions; for large tables, materialize a date-filtered slice before running evaluation jobs.

In Go, ContentFormatter receives the raw typed content payload: a string for a static AGENT_STARTING instruction, *genai.Content for USER_MESSAGE_RECEIVED, *model.LLMRequest for LLM_REQUEST, *model.LLMResponse for LLM_RESPONSE, and maps for tool and other map-shaped events. NODE_OUTPUT and A2A_INTERACTION pass through their original output/response values, which can also be slices or scalars. It does not transform attributes. In particular, STATE_DELTA stores its payload in attributes.state_delta and does not invoke ContentFormatter. Clone any pointer, slice, or map you modify (including Part.Text, Part.ExecutableCode.Code, Part.CodeExecutionResult.Output, Part.FunctionCall.Args, and Part.FunctionResponse.Response inside *genai.Content) and never mutate the live payload.

These helpers clone the values they edit and stop after 50 nesting levels. Excessively nested or cyclic payloads return an error, so the plugin records [FORMATTER_FAILED] instead of risking a process crash. These helpers recurse through JSON-shaped map[string]any and []any values (plus []string, map[string]string, and []map[string]any). Add bounded cases for any other concrete types your tools return, or normalize those values before formatting, and test the actual payloads before relying on this redaction:

package analytics

import (

var dollarPattern = regexp.MustCompile(`\$\d+(?:,\d{3})*(?:\.\d+)?`)

func maskContent(c *genai.Content, eventType string, depth int) (*genai.Content, error) {
    if depth >= 50 {
        return nil, fmt.Errorf("redaction nesting limit exceeded")
    }
    if c == nil {
        return nil, nil
    }
    cloned := *c
    if len(c.Parts) > 0 {
        cloned.Parts = make([]*genai.Part, len(c.Parts))
        for i, p := range c.Parts {
            if p == nil {
                continue
            }
            partCopy := *p
            if partCopy.Text != "" {
                partCopy.Text = dollarPattern.ReplaceAllString(partCopy.Text, "xxx")
            }
            if partCopy.ExecutableCode != nil {
                codeCopy := *partCopy.ExecutableCode
                codeCopy.Code = dollarPattern.ReplaceAllString(codeCopy.Code, "xxx")
                partCopy.ExecutableCode = &codeCopy
            }
            if partCopy.CodeExecutionResult != nil {
                resultCopy := *partCopy.CodeExecutionResult
                resultCopy.Output = dollarPattern.ReplaceAllString(resultCopy.Output, "xxx")
                partCopy.CodeExecutionResult = &resultCopy
            }
            if partCopy.FunctionCall != nil {
                fcCopy := *partCopy.FunctionCall
                if fcCopy.Args != nil {
                    redactedArgs, err := redactDollarAmountsAtDepth(fcCopy.Args, eventType, depth+1)
                    if err != nil {
                        return nil, err
                    }
                    if argsMap, ok := redactedArgs.(map[string]any); ok {
                        fcCopy.Args = argsMap
                    }
                }
                partCopy.FunctionCall = &fcCopy
            }
            if partCopy.FunctionResponse != nil {
                frCopy := *partCopy.FunctionResponse
                if frCopy.Response != nil {
                    redactedResp, err := redactDollarAmountsAtDepth(frCopy.Response, eventType, depth+1)
                    if err != nil {
                        return nil, err
                    }
                    if respMap, ok := redactedResp.(map[string]any); ok {
                        frCopy.Response = respMap
                    }
                }
                partCopy.FunctionResponse = &frCopy
            }
            cloned.Parts[i] = &partCopy
        }
    }
    return &cloned, nil
}

func redactDollarAmounts(payload any, eventType string) (any, error) {
    return redactDollarAmountsAtDepth(payload, eventType, 0)
}

func redactDollarAmountsAtDepth(payload any, eventType string, depth int) (any, error) {
    if depth >= 50 {
        return nil, fmt.Errorf("redaction nesting limit exceeded")
    }
    switch v := payload.(type) {
    case string:
        return dollarPattern.ReplaceAllString(v, "xxx"), nil
    case *genai.Content:
        return maskContent(v, eventType, depth+1)
    case *model.LLMRequest:
        if v == nil {
            return nil, nil
        }
        cloned := *v
        if len(v.Contents) > 0 {
            cloned.Contents = make([]*genai.Content, len(v.Contents))
            for i, c := range v.Contents {
                masked, err := maskContent(c, eventType, depth+1)
                if err != nil {
                    return nil, err
                }
                cloned.Contents[i] = masked
            }
        }
        if v.Config != nil && v.Config.SystemInstruction != nil {
            maskedSys, err := maskContent(v.Config.SystemInstruction, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cfgCopy := *v.Config
            cfgCopy.SystemInstruction = maskedSys
            cloned.Config = &cfgCopy
        }
        return &cloned, nil
    case *model.LLMResponse:
        if v == nil {
            return nil, nil
        }
        maskedContent, err := maskContent(v.Content, eventType, depth+1)
        if err != nil {
            return nil, err
        }
        cloned := *v
        cloned.Content = maskedContent
        return &cloned, nil
    case map[string]any:
        if v == nil {
            return map[string]any(nil), nil
        }
        cloned := make(map[string]any, len(v))
        for k, val := range v {
            redacted, err := redactDollarAmountsAtDepth(val, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[k] = redacted
        }
        return cloned, nil
    case map[string]string:
        if v == nil {
            return map[string]string(nil), nil
        }
        cloned := make(map[string]string, len(v))
        for k, val := range v {
            redacted, err := redactDollarAmountsAtDepth(val, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[k], _ = redacted.(string)
        }
        return cloned, nil
    case []any:
        if v == nil {
            return []any(nil), nil
        }
        cloned := make([]any, len(v))
        for i, item := range v {
            redacted, err := redactDollarAmountsAtDepth(item, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[i] = redacted
        }
        return cloned, nil
    case []string:
        if v == nil {
            return []string(nil), nil
        }
        cloned := make([]string, len(v))
        for i, item := range v {
            redacted, err := redactDollarAmountsAtDepth(item, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[i], _ = redacted.(string)
        }
        return cloned, nil
    case []map[string]any:
        if v == nil {
            return []map[string]any(nil), nil
        }
        cloned := make([]map[string]any, len(v))
        for i, item := range v {
            redacted, err := redactDollarAmountsAtDepth(item, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[i], _ = redacted.(map[string]any)
        }
        return cloned, nil
    default:
        return payload, nil
    }
}

    cfg.ContentFormatter = redactDollarAmounts

    }
    bqPlugin, ok := agentanalytics.AsBigQueryAgentAnalyticsPlugin(adkPlugin)
    if !ok {

    }

}

Automatically Created Views¶

Supported in ADKPython v1.27.0Go v0.1.0Java v1.5.0

In Python (create_views=True) and Go (DisableCreateViews: false), the plugin automatically generates views for each event type by default. In Java, set createViews(true); its default is false. Kotlin does not create views. The views unnest common JSON structures into flat, typed columns, which avoids repetitive JSON_VALUE and JSON_QUERY expressions.

View names follow the convention {view_prefix}_{event_type_lowercase} (for example, with the default prefix "v", LLM_REQUEST becomes v_llm_request). Set view_prefix in BigQueryLoggerConfig (ViewPrefix in Go's agentanalytics.Config) to a distinct value when multiple plugin instances write to different tables in the same dataset, preventing view-name collisions:

# Two plugins in the same dataset with distinct view prefixes
plugin_prod = BigQueryAgentAnalyticsPlugin(
    project_id=PROJECT_ID, dataset_id=DATASET_ID,
    table_id="agent_events_prod",
    config=BigQueryLoggerConfig(view_prefix="v_prod"),
)
# Creates views: v_prod_llm_request, v_prod_tool_completed, ...

plugin_staging = BigQueryAgentAnalyticsPlugin(
    project_id=PROJECT_ID, dataset_id=DATASET_ID,
    table_id="agent_events_staging",
    config=BigQueryLoggerConfig(view_prefix="v_staging"),
)
# Creates views: v_staging_llm_request, v_staging_tool_completed, ...

You can also refresh views on demand:

  • Python: Call await plugin.create_analytics_views() (and await plugin.create_eval_views() in Python v2.13.0+ for the agent evaluation views).
  • Go: Unwrap the plugin with bqPlugin, ok := agentanalytics.AsBigQueryAgentAnalyticsPlugin(adkPlugin) and call bqPlugin.SyncViews(ctx). If you constructed the plugin with NewBigQueryAgentAnalyticsPluginWithClients(..., nil, ...) (bqClient == nil), the plugin creates no views automatically and SyncViews returns agentanalytics: BigQuery client is not configured for view creation; use cfg.ViewDefinitions() (which returns Name, EventType, and Query) to inspect or execute the view DDL yourself.

Event types and payloads¶

The content column now contains a JSON object specific to the event_type. The content_parts column provides a structured view of the content, especially useful for images or offloaded data.

Content Truncation

  • Variable content fields are truncated to max_content_length (configured in BigQueryLoggerConfig, default 500KB).
  • If gcs_bucket_name is configured, large content is offloaded to GCS instead of being truncated, and a reference is stored in content_parts.object_ref.

LLM interactions (plugin lifecycle)¶

These events track the raw requests sent to and responses received from the LLM.

1. LLM_REQUEST

Captures the prompt sent to the model, including conversation history and system instructions.

{
  "event_type": "LLM_REQUEST",
  "content": {
    "system_prompt": "You are a helpful assistant...",
    "prompt": [
      {
        "role": "user",
        "content": "hello how are you today"
      }
    ]
  },
  "attributes": {
    "root_agent_name": "my_bq_agent",
    "model": "gemini-flash-latest",
    "tools": [
      {
        "name": "list_dataset_ids",
        "description": "..."
      },
      {
        "name": "execute_sql",
        "description": "..."
      }
    ],
    "llm_config": {
      "temperature": 0.5,
      "top_p": 0.9
    }
  }
}

The automatically created v_llm_request view exposes the tools attribute as its tools (JSON) column. In Python and Go, tools has one entry per tool with its name and, when available, its description and parameters (the tool's parameter schema). These entries pass through the same size limit and sensitive-key redaction as other attributes. Java records only the tool names, for example ["list_dataset_ids", "execute_sql"].

2. LLM_RESPONSE

Captures the model's output and token usage statistics.

{
  "event_type": "LLM_RESPONSE",
  "content": {
    "response": "text: 'Hello! I'm doing well...'",
    "usage": {
      "completion": 19,
      "prompt": 10129,
      "total": 10148
    }
  },
  "attributes": {
    "root_agent_name": "my_bq_agent",
    "model_version": "gemini-flash-latest",
    "usage_metadata": {
      "prompt_token_count": 10129,
      "candidates_token_count": 19,
      "total_token_count": 10148
    },
    "finish_reason": "STOP"
  },
  "latency_ms": {
    "time_to_first_token_ms": 2579,
    "total_ms": 2579
  }
}

The Python and Go plugins add finish_reason only to final, non-partial responses. Their v_llm_response views expose it as a STRING, along with the final response's cache_type. When the model supplies termination diagnostics, they store a sanitized value in the common error_message column even though the row's status remains OK.

In Python and Go, model finish and block reasons remain classified as LLM_RESPONSE. The plugin uses LLM_ERROR only when a model call fails with an error.

In Python and Go, content.response summarizes the response parts, separated by |, for example text: '...' for text, call: <name> for a function call, resp: <name> for a function response, and other for other part types. Text longer than max_content_length (MaxContentLen in Go) is cut, which sets is_truncated. In ADK Python v2.12.0+ and Go, the summary also shows executable code as Executable code (<language>): <code> and code execution results as Code execution result (<outcome>): <output>, redacts common credential patterns in text, code, and output, and ends cut values with ...[TRUNCATED]; redaction also sets is_truncated. When custom_metadata_allowlist (CustomMetadataAllowlist in Go) is set, the final (non-partial) LLM_RESPONSE row captures allowlisted keys from llm_response.custom_metadata into attributes.custom_metadata.

3. LLM_ERROR

Logged when an LLM call fails with an exception. The error message is captured and the span is closed.

{
  "event_type": "LLM_ERROR",
  "content": null,
  "attributes": {
    "root_agent_name": "my_bq_agent"
  },
  "error_message": "Error 429: Resource exhausted",
  "latency_ms": {
    "total_ms": 350
  }
}

Human-in-the-Loop (HITL) Events¶

The plugin automatically detects calls to ADK's synthetic HITL tools and emits dedicated event types for them. These events are logged in addition to the normal TOOL_STARTING / TOOL_COMPLETED events.

The following HITL tool names are recognized:

  • adk_request_credential: Request for user credentials (e.g., OAuth tokens)
  • adk_request_confirmation: Request for user confirmation before proceeding
  • adk_request_input: Request for free-form user input

HITL_CONFIRMATION_REQUEST Agent calls adk_request_confirmation {"tool": "adk_request_confirmation", "args": {...}}

Agent workflow and pause/resume events (ADK 2.0)¶

Supported in ADKPython v2.3.0Go v0.1.0Java v1.7.0

Java support

The Java plugin supports a subset of this section: it emits TOOL_PAUSED and the pause/resume pairing described below, but does not emit AGENT_TRANSFER, AGENT_STATE_CHECKPOINT, or EVENT_COMPACTION, and does not write the attributes.adk envelope. The Java plugin stores pause_kind and function_call_id at the top level of attributes instead (see the query note below).

ADK 2.0 introduced multi-agent workflows (agents that transfer control, checkpoint their state, and compact long histories) and long-running tools that pause and resume across turns. The plugin makes these flows observable with four new event types and a small metadata envelope, attributes.adk, that ties the rows back to the ADK event that produced them.

The attributes.adk envelope¶

The envelope is written by the Python and Go plugins. Every row carries an attributes.adk object. schema_version is always present (along with app_name in Python, and in Go whenever app_name is non-empty); event-originating fields are added for rows that originate from an ADK Event (lifecycle and workflow events), so on a callback-only row they are omitted and resolve to SQL NULL when queried.

Field Type Meaning
schema_version string Envelope version (currently "1"). Gate downstream queries on this when the envelope evolves.
app_name string The ADK app that produced the row (omitted in Go when empty).
source_event_id string ID of the originating ADK Event. The reliable key for joining the multiple rows a single event can produce.
node object Workflow node identity: { "path", "run_id", "parent_run_id" }. parent_run_id is the run ID of the parent node (null at the root). In Go, node also includes message_as_output (bool) and output_for (array of strings) when set on NodeInfo.
branch string The event's branch, when the workflow runs branched paths.
scope object Isolation scope { "id", "kind" }, where kind is node_run (a workflow node run, e.g. loopA@42), function_call (a model-generated call ID), or (Python) unknown.
route string or array The route selected by the event action (a string in Python, or an array of strings in Go), when set.
render_ui_widgets array Serialized UI widgets requested by the event action, when set (Python).
rewind_before_invocation_id string Invocation ID that the event action requests rewinding before, when set (Python).
pause_kind string On TOOL_PAUSED: tool for a regular long-running tool, or hitl_credential / hitl_confirmation / hitl_input for a HITL request. On a resumed TOOL_COMPLETED row it is always tool; HITL completions are logged as HITL_*_REQUEST_COMPLETED, never TOOL_COMPLETED.
function_call_id string The function call ID. Set on TOOL_PAUSED and on the matching resumed TOOL_COMPLETED row so the two can be paired (ordinary tools only).

In Go, attributes.adk also stamps event_id and author on every row, stamps adk_version and invocation_id when non-empty, stamps session_id and user_id when DisableSessionMetadata is false and the values are non-empty, and adds isolation_scope, artifact_delta, skip_summarization, and escalate on rows derived from an ADK session.Event when present.

Querying the envelope

Read envelope fields with JSON_VALUE(attributes, '$.adk.<field>') (or JSON_QUERY for the node / scope objects). The auto-created views already expose the commonly used fields (source_event_id, pause_kind, function_call_id) as flat columns, so most queries can use the view instead.

Supported in ADKPython v2.7.0Go v0.1.0

TOOL_PAUSED and pause/resume pairing¶

An ordinary long-running tool emits a TOOL_PAUSED row when it yields, and a TOOL_COMPLETED row when its result arrives, often on a later turn. Both rows carry the same function_call_id and a pause_kind of tool, so you can pair a pause with its completion and measure how long the tool was suspended. (HITL requests also emit TOOL_PAUSED, but their completions are logged differently; see the note below.)

{
  "event_type": "TOOL_PAUSED",
  "content": {
    "tool": "request_manager_approval",
    "args": { "amount": 5000 }
  },
  "attributes": {
    "adk": { "pause_kind": "tool", "function_call_id": "call-789" }
  }
}

Java attribute location

The Java plugin writes the pair keys at the top level of attributes, with no adk wrapper: "attributes": {"pause_kind": "tool", "function_call_id": "call-789"}. In the base-table query below, replace '$.adk.pause_kind' / '$.adk.function_call_id' with '$.pause_kind' / '$.function_call_id'. The view-based query works unchanged for both languages, because the views expose the keys as flat columns.

Java also stamps the same top-level pair keys on HITL_*_REQUEST_COMPLETED rows, so a HITL TOOL_PAUSED row can be joined directly to its completion on function_call_id in the base table (there is no dedicated view for HITL completions).

Relationship to HITL events

A HITL request (adk_request_confirmation, etc.) still emits its dedicated HITL_*_REQUEST event as described in HITL events. When that request is also long-running, the plugin additionally emits a TOOL_PAUSED row whose pause_kind identifies the HITL kind (for example hitl_confirmation), which gives HITL pauses the same visibility as tool pauses.

A HITL completion does not arrive as TOOL_COMPLETED, though. The user's response is logged as the corresponding HITL_*_REQUEST_COMPLETED event, not TOOL_COMPLETED, so a hitl_* pause will not pair through the tool join below. To see a HITL pause resolve, look to its HITL_*_REQUEST_COMPLETED event (see HITL events). The pause/resume queries below are therefore scoped to ordinary tools (pause_kind = 'tool').

Pair paused tools with their completions using the shared keys. On the base table:

SELECT
  p.timestamp AS paused_at,
  c.timestamp AS resumed_at,
  TIMESTAMP_DIFF(c.timestamp, p.timestamp, SECOND) AS paused_seconds,
  JSON_VALUE(p.content, '$.tool') AS tool_name,
  JSON_VALUE(p.attributes, '$.adk.pause_kind') AS pause_kind
FROM `your-gcp-project-id.adk_agent_logs.agent_events` AS p
JOIN `your-gcp-project-id.adk_agent_logs.agent_events` AS c
  ON  c.event_type = 'TOOL_COMPLETED'
  AND c.session_id = p.session_id
  AND c.user_id = p.user_id
  AND JSON_VALUE(c.attributes, '$.adk.function_call_id')
      = JSON_VALUE(p.attributes, '$.adk.function_call_id')
WHERE p.event_type = 'TOOL_PAUSED'
  AND JSON_VALUE(p.attributes, '$.adk.pause_kind') = 'tool'
ORDER BY paused_at;

Or, more simply, against the auto-created views, which expose pause_kind and function_call_id as flat columns:

SELECT
  p.timestamp AS paused_at,
  c.timestamp AS resumed_at,
  TIMESTAMP_DIFF(c.timestamp, p.timestamp, SECOND) AS paused_seconds,
  p.tool_name,
  p.pause_kind
FROM `your-gcp-project-id.adk_agent_logs.v_tool_paused` AS p
JOIN `your-gcp-project-id.adk_agent_logs.v_tool_completed` AS c
  USING (session_id, user_id, function_call_id)
WHERE p.pause_kind = 'tool'
ORDER BY paused_at;

Storage behavior: GCS offloading¶

When gcs_bucket_name is configured in BigQueryLoggerConfig (GCSBucketName or GCSOffloader in Go's agentanalytics.Config), the plugin automatically offloads large text and multimodal content (images, audio, etc.) to Google Cloud Storage. The content column will contain a summary or placeholder, while content_parts stores the object_ref pointing to the GCS URI. See also connection_id (ConnectionID in Go), max_content_length (MaxContentLen and MaxInlineTextSize in Go), and the Go upload concurrency/memory bounds (GCSMaxConcurrentUploads, GCSUploadTimeout, GCSMaxPendingUploadBytes) in Configuration options.

In Go, offloaded objects use the UTC date of the row's timestamp in their object path ([prefix/]<YYYY-MM-DD>/<trace_id>/<span_id>_<event_id>_c<ord>_p<idx><ext>), record "size" alongside "content_type" in object_ref.details.gcs_metadata (using "text/plain; charset=utf-8" as the GCS object content_type for offloaded text while keeping content_parts[].mime_type as "text/plain"), and also populate content_parts for LLM_RESPONSE events in addition to USER_MESSAGE_RECEIVED and LLM_REQUEST.

AI-powered root cause analysis¶

Automatically analyze failed sessions to determine the root cause of errors using BigQuery ML and Gemini.

DECLARE failed_session_id STRING;
-- Find a recent failed session
SET failed_session_id = (
    SELECT session_id
    FROM `your-gcp-project-id.your-dataset-id.agent_events`
    WHERE error_message IS NOT NULL
    ORDER BY timestamp DESC
    LIMIT 1
);

-- Reconstruct the full conversation context
WITH SessionContext AS (
    SELECT
        session_id,
        STRING_AGG(CONCAT(event_type, ': ', COALESCE(TO_JSON_STRING(content), '')), '\n' ORDER BY timestamp) as full_history
    FROM `your-gcp-project-id.your-dataset-id.agent_events`
    WHERE session_id = failed_session_id
    GROUP BY session_id
)
-- Ask Gemini to diagnose the issue
SELECT
    session_id,
    AI.GENERATE(
        ('Analyze this conversation log and explain the root cause of the failure. Log: ', full_history),
        endpoint => 'gemini-flash-latest'
    ).result AS root_cause_explanation
FROM SessionContext;

The context graph¶

Beyond row-level agent_events, the BigQuery Agent Analytics SDK can materialize a context graph: a queryable BigQuery property graph of your agent's decisions, including the requests it handled, the options it weighed, and the outcomes it chose. It lets you trace why a decision happened with Graph Query Language (GQL), not just that an event was logged.

The graph is defined by two declarative artifacts: your table DDL and a CREATE PROPERTY GRAPH schema. The SDK's bqaa context-graph --property-graph command derives the extraction (which entities and relationships to pull, and their column types) from them plus your live table schemas. No separate ontology or binding file is required for the common case; reach for an explicit ontology.yaml / binding.yaml only when you need descriptions to steer the AI prompt, entity inheritance, derived properties, or column renames.

Run it once locally, or on a schedule as a Cloud Run Job triggered by Cloud Scheduler, with split read-only-events / writable-graph datasets, least-privilege service accounts, structured JSON logs, and Cloud Monitoring alerts. Deploy to Agent Runtime with the plugin¶

You can deploy an agent with the BigQuery Agent Analytics plugin to Agent Runtime. This section walks through the steps to deploy using the ADK CLI, and alternatively using the Agent Platform SDK programmatically.

Version Requirement

Use ADK Python version 1.24.0 or higher to deploy with this plugin to Agent Runtime. Earlier versions had an issue where the plugin's asynchronous log writer could be terminated by the serverless runtime before flushing pending events. Starting from 1.24.0, the plugin performs a synchronous flush at the end of each invocation to ensure all events are written.

Prerequisites¶

Before deploying, ensure you have completed the general Agent Runtime setup, including:

  1. A Google Cloud project with the Agent Platform API and Cloud Resource Manager API enabled.
  2. A BigQuery dataset in the target project (or a cross-project dataset with the correct permissions).
  3. A Cloud Storage staging bucket for deployment artifacts.
  4. The deploying service account has the IAM roles listed in IAM permissions.
  5. Your coding environment is authenticated with gcloud auth login and gcloud auth application-default login.

Troubleshooting¶

If events are not appearing in your BigQuery table after deployment:

  1. Check ADK version and extra: Ensure google-adk[bigquery-analytics]>=2.7.0 is in your requirements. The extra installs the Storage Write API, Cloud Storage, and pyarrow dependencies required by the plugin.

  2. Enable debug logging: Add the following to the top of your agent.py to surface any silent errors:

    import logging
logging.basicConfig(level=logging.INFO)
logging.getLogger("google_adk").setLevel(logging.DEBUG)

  3. Check IAM permissions: The Agent Runtime service account needs roles/bigquery.dataEditor on the target table and roles/bigquery.jobUser on the project. For cross-project logging, also ensure the BigQuery API is enabled in the source project and the service account has bigquery.tables.updateData on the destination table.

  4. Verify plugin initialization: In Cloud Logging, filter by resource.type="reasoning_engine" and look for plugin startup messages or error logs.

  5. Use immediate flush for debugging: Set batch_size=1 and batch_flush_interval=0.1 in BigQueryLoggerConfig to rule out buffering issues.

Security: Avoid logging sensitive credentials¶

Do not log OAuth tokens, API keys, or client secrets

The BigQuery Agent Analytics plugin captures detailed event payloads, including tool arguments, LLM prompts, and authentication-related events (such as HITL credential requests). In Python, built-in redaction matches key names exactly after lowercasing and hyphen normalization, so camelCase variants such as clientSecret or accessToken are not matched. Go additionally ignores underscore and hyphen separators and does match those variants; the rest of this warning concerns Python's credential-request payload. ADK serializes adk_request_credential arguments with camelCase aliases, so an AuthenticatedFunctionTool OAuth2 flow can write client_secret and access_token values into the content column (google/adk-python#3845). ADK Python v2.9.0 and later remove the configured OAuth2 client secret from the adk_request_credential request, and ADK Python v2.12.0 and later also remove API keys, HTTP Basic passwords, HTTP bearer tokens, and additional HTTP headers from it. OAuth2 access tokens are still not removed. Fields that ADK does not remove from that request keep their camelCase names and are not matched by built-in redaction; neither are camelCase keys in your own tool arguments. Redaction is not a general data-loss prevention system: a secret under an application-specific key or in free-form text can also be written to BigQuery.

The plugin includes built-in redaction that automatically protects common secrets. For additional control, you can layer custom redaction on top.

Built-in redaction¶

Supported in ADKPythonGo v0.1.0Java v1.7.0

The Python plugin normalizes key names to lowercase and treats hyphens like underscores. It recursively replaces values with [REDACTED] for these keys wherever they appear in structured content or attributes:

client_secret, access_token, refresh_token, id_token, api_key, password, private_key, proxy_authorization, google_access_id, sig, signature, token, secret, authorization, x_api_key, x_amz_credential, x_amz_signature, x_goog_credential, x_goog_security_token, x_goog_signature

Python replaces temp: state values with [REDACTED]. Go removes top-level lowercase temp: entries from state_delta before logging and emits no STATE_DELTA row if nothing remains. Other temp: values in structured content and attributes are replaced with [REDACTED]. A secret: prefix has no special meaning. Use temp: for invocation-local sensitive state, or sanitize application-specific state values before they reach logging. Custom content formatters do not redact state attributes.

Correction to earlier guidance

An earlier version of this page stated that a secret: state prefix was automatically redacted. That was incorrect: ADK defines only the app:, user:, and temp: state scopes, and the plugin redacts only temp:. If you relied on that guidance, audit your existing agent_events tables for values logged under non-temp: keys.

The plugin also sanitizes credential patterns in error_message, agent and run tracebacks, and external URIs. This includes authorization headers, bearer and basic credentials, signed-URL query parameters, and key/value fragments that use the sensitive names above. Encoded credential constructs that cannot be safely rewritten fail closed.

No configuration required

Built-in redaction is always active for structured attributes and state logging, and applies recursively to nested dictionaries and JSON-encoded strings within attribute values. Custom content_formatter runs first on raw content. If it raises or returns an unsupported type, Python writes [FORMATTER_FAILED] instead of the original content and increments the formatter_failed incident counter.

A Python content_formatter can return None, a str, dict, or list (or a subclass of one), or an exact types.Content, types.Part, or LlmRequest. In ADK Python v2.11.0 and later, a formatter failure is also recorded in the row's error_message, which names only the exception or return-value class, for example content_formatter raised ImportError, content_formatter raised <subclass of ValueError>, or content_formatter returned unsupported type tuple. If the event already has an error_message, such as a TOOL_ERROR, that message stays first, followed by a semicolon and the formatter failure. The row's status is unchanged, so an otherwise successful event keeps status OK, but queries that treat any non-null error_message as an error still flag the row.

To debug a formatter that raises, set debug_content_formatter_errors=True to append a bounded traceback to the plugin's Python log warning. The traceback can include the unformatted content and reaches every configured log handler, so enable it only where that content may be seen. It is never written to BigQuery.

Built-in redaction in Go

The Go plugin (google.golang.org/adk/plugin/agentanalytics) enables built-in redaction by default (DisableSensitiveKeyRedaction: false). Key names are normalized by lowercasing and stripping underscores (_) and hyphens (-), so snake_case, kebab-case, and camelCase variants (such as api_key, api-key, apiKey, clientSecret, accessToken, refreshToken, idToken, privateKey, sessionToken, secretAccessKey, codeVerifier, authCode, and passphrase) are matched and replaced with "[REDACTED]" across structured content and attributes (unless DisableSensitiveKeyRedaction: true).

In addition, the Go plugin:

  • Removes top-level lowercase temp: entries from state_delta before logging and emits no STATE_DELTA row if nothing remains; replaces other temp: values in structured content and attributes with "[REDACTED]"; and redacts whole credential-container envelopes under credential or credentials.
  • Scrubs credential userinfo and sensitive query parameters from external URIs (failing closed to "[REDACTED_SENSITIVE_URI]" when a sensitive query value cannot be safely rewritten), and scrubs Authorization headers, Bearer and Basic tokens, and embedded JSON credential fragments in error_message and uri.
  • Runs custom ContentFormatter (func(content any, eventType string) (any, error)) before built-in redaction. If ContentFormatter returns a non-nil error or panics, the Go plugin writes "[FORMATTER_FAILED]" to content, writes no content_parts, appends content_formatter raised <error type> or content_formatter panicked to error_message, and increments DropStats().FormatterFailureDrops.

Built-in redaction in Java

The Java plugin includes built-in redaction in v1.7.0 and later. It redacts client_secret, access_token, refresh_token, id_token, api_key, and password (case-insensitive) recursively across the assembled attributes tree, including session state and state deltas, and any key prefixed with temp:. Keep secrets out of other state scopes or mask them with a custom contentFormatter.

A custom Java contentFormatter must be thread-safe (it is called concurrently across invocations) and fast/non-blocking (it runs on the event-processing path), and it must return a new object rather than mutating the content it receives. If it throws, the Java plugin drops the row's content (fail-closed) rather than logging the unformatted payload.

Use content_formatter to redact additional secrets¶

Provide a custom content_formatter function (ContentFormatter in Go, contentFormatter in Java) to strip or mask sensitive fields before they are written:

import json
import re
from typing import Any

SENSITIVE_KEYS = {"client_secret", "access_token", "refresh_token", "api_key", "secret"}

def redact_credentials(event_content: Any, event_type: str) -> str:
    """Redact OAuth secrets and tokens from logged content."""
    if isinstance(event_content, dict):
        text = json.dumps(event_content)
    else:
        text = str(event_content)

    for key in SENSITIVE_KEYS:
        # Redact values in JSON-like strings: "client_secret": "GOCSPX-xxx"
        text = re.sub(
            rf'("{key}"\s*:\s*)"[^"]*"',
            rf'\1"[REDACTED]"',
            text,
            flags=re.IGNORECASE,
        )
    return text

config = BigQueryLoggerConfig(
    content_formatter=redact_credentials,
    # ... other options
)

In Go the formatter receives the raw typed content payload (such as string, *genai.Content, *model.LLMRequest, *model.LLMResponse, or map[string]any), not the final JSON, and does not transform attributes such as attributes.state_delta. Clone any pointer, slice, or map you modify (including Part.Text, Part.ExecutableCode.Code, Part.CodeExecutionResult.Output, Part.FunctionCall.Args, and Part.FunctionResponse.Response inside *genai.Content) and never mutate the live payload.

These helpers clone the values they edit and stop after 50 nesting levels. Excessively nested or cyclic payloads return an error, so the plugin records [FORMATTER_FAILED] instead of risking a process crash. These helpers recurse through JSON-shaped map[string]any and []any values (plus []string, map[string]string, and []map[string]any). Add bounded cases for any other concrete types your tools return, or normalize those values before formatting, and test the actual payloads before relying on this redaction:

var ssnPattern = regexp.MustCompile(`\b\d{3}-\d{2}-\d{4}\b`)

func redactCustomSecrets(content any, eventType string) (any, error) {
    return redactCustomSecretsAtDepth(content, eventType, 0)
}

func redactCustomSecretsAtDepth(content any, eventType string, depth int) (any, error) {
    if depth >= 50 {
        return nil, fmt.Errorf("redaction nesting limit exceeded")
    }
    switch v := content.(type) {
    case string:
        return ssnPattern.ReplaceAllString(v, "[REDACTED_SSN]"), nil
    case *genai.Content:
        return redactGenAIContentSecrets(v, eventType, depth+1)
    case *model.LLMRequest:
        if v == nil {
            return nil, nil
        }
        cloned := *v
        if len(v.Contents) > 0 {
            cloned.Contents = make([]*genai.Content, len(v.Contents))
            for i, c := range v.Contents {
                redactedContent, err := redactGenAIContentSecrets(c, eventType, depth+1)
                if err != nil {
                    return nil, err
                }
                cloned.Contents[i] = redactedContent
            }
        }
        if v.Config != nil && v.Config.SystemInstruction != nil {
            redactedSys, err := redactGenAIContentSecrets(v.Config.SystemInstruction, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cfgCopy := *v.Config
            cfgCopy.SystemInstruction = redactedSys
            cloned.Config = &cfgCopy
        }
        return &cloned, nil
    case *model.LLMResponse:
        if v == nil {
            return nil, nil
        }
        redactedContent, err := redactGenAIContentSecrets(v.Content, eventType, depth+1)
        if err != nil {
            return nil, err
        }
        cloned := *v
        cloned.Content = redactedContent
        return &cloned, nil
    case map[string]any:
        if v == nil {
            return map[string]any(nil), nil
        }
        cloned := make(map[string]any, len(v))
        for k, val := range v {
            if depth+1 >= 50 {
                return nil, fmt.Errorf("redaction nesting limit exceeded")
            }
            if strings.EqualFold(k, "internal_token") {
                cloned[k] = "[REDACTED]"
                continue
            }
            redactedVal, err := redactCustomSecretsAtDepth(val, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[k] = redactedVal
        }
        return cloned, nil
    case map[string]string:
        if v == nil {
            return map[string]string(nil), nil
        }
        cloned := make(map[string]string, len(v))
        for k, val := range v {
            if depth+1 >= 50 {
                return nil, fmt.Errorf("redaction nesting limit exceeded")
            }
            if strings.EqualFold(k, "internal_token") {
                cloned[k] = "[REDACTED]"
                continue
            }
            redactedVal, err := redactCustomSecretsAtDepth(val, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[k], _ = redactedVal.(string)
        }
        return cloned, nil
    case []any:
        if v == nil {
            return []any(nil), nil
        }
        cloned := make([]any, len(v))
        for i, item := range v {
            redactedItem, err := redactCustomSecretsAtDepth(item, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[i] = redactedItem
        }
        return cloned, nil
    case []string:
        if v == nil {
            return []string(nil), nil
        }
        cloned := make([]string, len(v))
        for i, item := range v {
            redactedItem, err := redactCustomSecretsAtDepth(item, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[i], _ = redactedItem.(string)
        }
        return cloned, nil
    case []map[string]any:
        if v == nil {
            return []map[string]any(nil), nil
        }
        cloned := make([]map[string]any, len(v))
        for i, item := range v {
            redactedItem, err := redactCustomSecretsAtDepth(item, eventType, depth+1)
            if err != nil {
                return nil, err
            }
            cloned[i], _ = redactedItem.(map[string]any)
        }
        return cloned, nil
    default:
        return content, nil
    }
}

func redactGenAIContentSecrets(c *genai.Content, eventType string, depth int) (*genai.Content, error) {
    if depth >= 50 {
        return nil, fmt.Errorf("redaction nesting limit exceeded")
    }
    if c == nil {
        return nil, nil
    }
    cloned := *c
    if len(c.Parts) > 0 {
        cloned.Parts = make([]*genai.Part, len(c.Parts))
        for i, p := range c.Parts {
            if p == nil {
                continue
            }
            partCopy := *p
            if partCopy.Text != "" {
                partCopy.Text = ssnPattern.ReplaceAllString(partCopy.Text, "[REDACTED_SSN]")
            }
            if partCopy.ExecutableCode != nil {
                codeCopy := *partCopy.ExecutableCode
                codeCopy.Code = ssnPattern.ReplaceAllString(codeCopy.Code, "[REDACTED_SSN]")
                partCopy.ExecutableCode = &codeCopy
            }
            if partCopy.CodeExecutionResult != nil {
                resultCopy := *partCopy.CodeExecutionResult
                resultCopy.Output = ssnPattern.ReplaceAllString(resultCopy.Output, "[REDACTED_SSN]")
                partCopy.CodeExecutionResult = &resultCopy
            }
            if partCopy.FunctionCall != nil {
                fcCopy := *partCopy.FunctionCall
                if fcCopy.Args != nil {
                    redactedArgs, err := redactCustomSecretsAtDepth(fcCopy.Args, eventType, depth+1)
                    if err != nil {
                        return nil, err
                    }
                    if argsMap, ok := redactedArgs.(map[string]any); ok {
                        fcCopy.Args = argsMap
                    }
                }
                partCopy.FunctionCall = &fcCopy
            }
            if partCopy.FunctionResponse != nil {
                frCopy := *partCopy.FunctionResponse
                if frCopy.Response != nil {
                    redactedResp, err := redactCustomSecretsAtDepth(frCopy.Response, eventType, depth+1)
                    if err != nil {
                        return nil, err
                    }
                    if respMap, ok := redactedResp.(map[string]any); ok {
                        frCopy.Response = respMap
                    }
                }
                partCopy.FunctionResponse = &frCopy
            }
            cloned.Parts[i] = &partCopy
        }
    }
    return &cloned, nil
}

General best practices¶

  • Never hardcode secrets in agent source code. Use environment variables or a secret manager (e.g., Google Cloud Secret Manager) for OAuth client secrets and API keys.
  • Restrict BigQuery table access using IAM to limit who can read logged event data.
  • Audit your logs periodically to verify no unexpected sensitive data is being captured.

Operations¶

Tracing and observability¶

The plugin populates the trace_id, span_id, and parent_span_id columns on every emitted row so the parent-child execution tree (Agent → LLM call / Tool call) reconstructs cleanly from BigQuery.

  • Internal span tracking, no OTel span export. The plugin tracks the parent-child hierarchy on its own internal stack of 16-hex span_id values. In Python and Java, the root invocation span reuses the ambient OTel span's id when one is active (so it lines up with the runner's invocation span); in Go, the plugin always generates its own 16-hex root span_id and records any ambient OTel span ID in parent_span_id. Child BQAA spans are generated internally. It does not call tracer.start_span(...) on any configured OpenTelemetry TracerProvider, so its instrumentation never reaches your configured exporter. This is what prevents duplicate spans in Cloud Trace when Agent Engine telemetry is enabled (GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true) or when you wire any other Cloud Trace exporter into the host process. The same internal, ID-only span tracking applies to the Go plugin and the Java plugin (v1.7.0+); earlier Java builds created plugin-owned OpenTelemetry spans that could surface as duplicates next to framework spans.
  • trace_id inherited from the ambient OTel span when present. If the surrounding runtime has already started an OTel span—such as Agent Engine's invocation span, the ADK Runner invocation span (in Python and Java), or any span you opened before the agent runs—the plugin reads its trace_id and stamps it on every BigQuery row. BigQuery rows therefore join cleanly to your existing Cloud Trace traces via a shared trace_id.
  • Fallback when no ambient span is present. If no ambient OTel span is active (e.g. a non-Agent-Engine deployment with no host-side tracer configured), Python generates a random per-invocation 32-hex trace_id. Without an ambient span, Go generates a random 32-hex trace_id when invocation_id is empty. Otherwise, it uses SHA-256 over a random per-plugin seed and the invocation ID, producing a stable 32-hex ID within that plugin instance. Java falls back to the ADK invocation ID as the trace_id, so the parent-child hierarchy is always preserved in BigQuery, even without any external tracer setup.
  • No TracerProvider is required. Configuring an OpenTelemetry TracerProvider in your host process is optional. It only matters if you want the plugin's trace_id to be sourced from your own pre-existing ambient span (e.g. to correlate against telemetry from non-ADK services). The plugin no longer needs the provider for its own bookkeeping.

If you relied on the plugin to feed your OTel exporter

Some older configurations used the BQAA plugin as a side channel for OpenTelemetry span emission; that path is intentionally gone. Configure OTel instrumentation in the host application instead (Agent Engine wires this automatically; for local deployments use ADK's own framework instrumentation or an explicit TracerProvider). The plugin's BigQuery rows will continue to join to your traces via trace_id.

Public methods¶

The plugin exposes several public methods for lifecycle management:

  • await plugin.flush(): Wait for pending events associated with the current event loop to finish writing.
  • await plugin.shutdown(timeout=None, *, close_background_transport=False): Gracefully shut down the plugin, flushing pending events and releasing resources. The optional timeout parameter overrides shutdown_timeout from the config. If the plugin uses the shared background writer, shutdown detaches the plugin from that writer and leaves the writer running. Pass close_background_transport=True to also drain and stop the shared writer for this plugin's table and credentials.
  • await plugin.close(timeout=None, *, close_background_transport=False): Run the plugin-manager lifecycle contract. It delegates to shutdown() with the same arguments and is called automatically when a runner closes its plugins.
  • await BigQueryAgentAnalyticsPlugin.close_shared_background_transports(timeout=10.0) (Python v2.10.0+): Drain and stop every shared background writer in the process, for example in a standalone script, a process shutdown handler, or a test cleanup fixture. It raises an exception if a writer fails to drain or doesn't finish within timeout: the writer's error or a TimeoutError when one writer fails, or a RuntimeError when several fail. The same operation is available as the module-level function close_shared_background_transports(timeout=10.0) in google.adk.plugins.bigquery_agent_analytics_plugin.
  • await plugin.create_analytics_views(): Manually (re-)create all per-event-type analytics views. Useful after a schema upgrade or when views need to be refreshed.
  • await plugin.create_eval_views() (Python v2.13.0+): Manually (re-)create the agent evaluation views ({view_prefix}_eval_session and {view_prefix}_eval_turn), even when create_eval_views=False. See Agent evaluation views.
  • plugin.get_drop_stats(): Return a snapshot of delivery-loss and content-sanitization incident counts per reason. See Dropped-event observability below.

  • Async context manager: The plugin supports async with for automatic startup and shutdown:

    async with BigQueryAgentAnalyticsPlugin(
    project_id=PROJECT_ID, dataset_id=DATASET_ID
) as plugin:
    # plugin is initialized and ready to use
    ...
# plugin.shutdown() is called automatically on exit

In Go (google.golang.org/adk/plugin/agentanalytics), the plugin lifecycle and operational helpers are exposed through the ADK *plugin.Plugin handle and the unwrapped *agentanalytics.BigQueryAgentAnalyticsPlugin:

  • adkPlugin.Close() error: Drains queued events, stops the background batch processor (with each flush/upload stage bounded by ShutdownTimeout, default 10s, up to ~2.5x total wall-clock time), and closes plugin-owned BigQuery, Storage Write, and GCS clients.   • bqPlugin.DropStats() agentanalytics.DropStats: Returns a snapshot of dropped-event and formatter-failure counts (QueueFullDrops, AppendFailureDrops, FormatterFailureDrops, ShutdownDrops, and TotalDrops). See Dropped-event observability.

Dropped-event observability¶

Supported in ADKPythonGo v0.1.0Java v1.7.0

BigQuery logging is best-effort. Events can be dropped when the in-memory queue overflows, setup is unavailable, shutdown races a callback, or a write ultimately fails. The plugin also counts formatter and parser failures where the row is written with a sentinel in place of its content. The counters persist across loop cleanup and shutdown.

Drop reasons (Python):

Reason Cause
queue_full Bounds the in-memory event queue. In ADK Python v2.13.0, all event types share this capacity; terminal INVOCATION_COMPLETED and INVOCATION_ERROR rows can also be dropped when it is full and are counted under queue_full. Increase queue_max_size on BigQueryLoggerConfig, raise batch_size to drain in larger chunks, or scale the consumer side (more concurrent invocations finishing faster).
arrow_prep_failed A row could not be converted to its Arrow representation (typically schema/type mismatch). Inspect logs for the offending field.
retry_exhausted The Storage Write API call kept returning a retryable error (e.g. transient gRPC failures) until the retry budget was used up.
permission_denied (Python v2.13.0+) Storage Write API returned PERMISSION_DENIED (google.api_core.exceptions.PermissionDenied). Non-retryable; check that the service account has bigquery.tables.updateData (e.g., roles/bigquery.dataEditor) on the target table.
not_found (Python v2.13.0+) Storage Write API returned NOT_FOUND (google.api_core.exceptions.NotFound) on the default stream, such as when the target dataset, table, or write stream does not exist (NOT_FOUND in exactly_once_delivery mode is counted under offset_conflict). Non-retryable.
non_retryable Storage Write API returned another non-retryable error (quota, schema rejection, invalid argument). Usually requires operator intervention.
unexpected_error Any other exception caught while preparing or writing the batch.
shutdown_timeout Rows remained queued when a bounded shutdown or close timed out.
shutdown_cancelled Rows remained queued when shutdown was cancelled by the host, such as by an outer close timeout.
offset_conflict In exactly_once_delivery mode, a committed stream rejected an offset or a replacement stream was unavailable.
setup_unavailable A row could not be admitted because plugin setup failed or remained in retry backoff.
shutdown_race A callback attempted to admit a row while shutdown was starting or in progress.
stale_loop Queued rows belonged to an event loop that had already closed and could no longer drain them.
formatter_failed The custom formatter failed or returned an unsupported type. The row is still written with [FORMATTER_FAILED]; this is an incident count, not a dropped-row count.
content_parse_failed Content parsing failed. The row is still written with [CONTENT_PARSE_FAILED]; this is an incident count, not a dropped-row count.

Drop counters (Go):

bqPlugin.DropStats() returns an agentanalytics.DropStats struct with the following int64 fields:

Field Cause
QueueFullDrops Rows dropped because the in-memory channel (QueueMaxSize, default 10000) was full when an event callback or Append tried to queue a row. Increase QueueMaxSize or BatchSize on agentanalytics.Config.
AppendFailureDrops Rows recorded as failed during Storage Write API delivery (including batches that exhausted MaxRetries, non-retryable write or schema/descriptor preparation errors, server-committed appends whose ack was lost on a broken stream before retry failed, recovered callback panics, and remaining batches skipped after a batch failure in Flush).
FormatterFailureDrops Custom ContentFormatter invocations that returned a non-nil error or panicked. The row is still written with "[FORMATTER_FAILED]", no content_parts, and content_formatter raised <error type> or content_formatter panicked in error_message; this is an incident count, not included in TotalDrops.
ShutdownDrops Rows remaining in the queue that could not be drained before ShutdownTimeout expired during Close(), plus rows passed to Append after Close() has started.
TotalDrops Upper-bound total of rows counted as dropped (QueueFullDrops + AppendFailureDrops + ShutdownDrops). Because AppendFailureDrops can include server-committed batches whose ack was lost, TotalDrops is an upper bound on lost rows.

Drop reasons (Java, v1.7.0+):

Reason Cause
queue_full The in-memory batch queue overflowed. Increase queueMaxSize on BigQueryLoggerConfig, raise batchSize, or scale the consumer side.
append_error Batch preparation or append failed for a cause other than AppendSerializationError, including timeouts, exhausted or non-retryable writes, and unexpected conversion failures.
serialization_error A row could not be serialized for the write stream (typically a schema/type mismatch). Inspect logs for the offending field.
after_close A row reached an already-closed per-invocation processor.
shutdown_timeout Queued rows remained when the bounded final drain expired.
writer_permit_exhausted The live-writer safety cap was exhausted, normally during a Storage Write outage or delayed cleanup.
writer_create_error StreamWriter construction or processor startup failed.
late_after_finalize Async work completed after its invocation was finalized or while the plugin was closing.

Alert on every non-zero reason. Most reasons mean rows were lost before reaching BigQuery. The formatter_failed (FormatterFailureDrops in Go) and content_parse_failed reasons instead mean the row landed with sentinel content, so alert on them as privacy or data quality incidents. Sustained queue_full, retry_exhausted, permission_denied, not_found, non_retryable, or offset_conflict counts generally indicate throughput, IAM, delivery, or Storage Write health problems. In Go, the comparable write-error counter is AppendFailureDrops; in Java, it is append_error.

Multiprocessing and fork safety¶

The Python plugin is fork-aware: it sets GRPC_ENABLE_FORK_SUPPORT=1 before loading the gRPC C-core library and registers an os.register_at_fork handler that resets inherited runtime state (gRPC channels, write streams, event loops) in child processes. This means the plugin can survive os.fork() without leaking file descriptors or sending data on a parent's connection.

However, spawn is the recommended multiprocessing start method for production deployments. fork copies the parent's address space, including any in-flight gRPC state, and the post-fork reset adds latency to the first write in each child. With spawn, each worker initializes the plugin cleanly.

For Gunicorn deployments specifically:

  • Prefer --preload combined with lazy plugin initialization (the plugin defers setup until the first event is logged), or
  • Initialize the plugin inside a post_fork hook so each worker gets its own client.

Note

The fork-safety mechanism resets runtime state only. It does not replay events that were queued but not yet flushed in the parent process at the time of fork. Call await plugin.flush() before forking if you need to guarantee delivery.

Additional ways to consume logged data¶

BigQuery Agent Analytics SDK¶

The BigQuery Agent Analytics SDK provides a programmatic way to consume and analyze the data logged by the plugin. Use the SDK for:

  • Agent evaluation: Compare agent runs against expected outcomes
  • Golden trajectory matching: Validate that agent execution paths match approved sequences
  • Trace visualization: Reconstruct and visualize agent execution flows from logged spans

Build a dashboard¶

Visualize your agent's performance data with a hosted Looker Studio template, a ready-made Looker Block, or your own dashboard built from the example notebook.

Looker Studio template¶

The BigQuery Agent Analytics dashboard setup page is a quick way to get started. Enter the fully qualified ID of your event table (project.dataset.table) and it builds a Looker Studio link that creates your own private copy of a published template with prebuilt report pages, querying the base table directly with no generated views and no data pipelines. The setup page states that it has no backend and builds the link client-side; review its source before entering a table ID.

The copy is created with Owner's credentials. Keep the report private until you switch the data source to Viewer's credentials, so that each viewer queries BigQuery with their own access, and verify the switch with a viewer-only account before sharing.

Looker Block¶

The BigQuery Agent Analytics Looker Block provides a ready-to-use dashboard for monitoring, debugging, and optimizing your agents, with insights into interactions, tool usage, LLM performance, and cost footprints. It surfaces:

  • Aggregate metrics: token consumption, user engagement, and tool execution volumes.
  • System health: P50–P99 latency distributions and tool failure tracking to help you pinpoint bottlenecks.
  • Interactive drilldowns: click a metric to open context-aware visualizations for root-cause analysis.

The block uses a Native Derived Table architecture that parses the logged JSON payloads directly, so no additional data pipelines are required. To get started, install it for free from the Looker Marketplace and point it at your BigQuery project ID, dataset name, and base table name.

Custom dashboard from a notebook¶

The BigQuery Agent Analytics SDK includes an example Jupyter notebook that demonstrates how to query and visualize your agent's performance data. Use it as a starting point to build your own custom dashboards tailored to your BigQuery Agent Analytics dataset. You can also publish the notebook as an interactive dashboard using Colab Data Apps.
